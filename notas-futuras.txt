# Ideas para futuras mejoras del TFC (Transportes)

## Sistema Híbrido de APIs (Paradas + Ubicación en Vivo)
Actualmente usamos el CRTM público para todo, lo cual produce fallos de red por rate-limiting (Error 500, ERR_EMPTY_RESPONSE).

**Propuesta de mejora futura:**
- **Tiempos de Paradas (Popup):** Buscar e integrar una Transit API externa (ej. `HERE Public Transit API` de developer.here.com, o `Navitia.io`). Tienen cuentas gratuitas para estudiantes/desarrolladores. De esta forma, al hacer clic en una marquesina, los tiempos cargaían INSTANTÁNEAMENTE y sin errores estandarizados. (No se puede usar Google Maps Platform porque no ofrecen un endpoint puro para paradas sin enrutar).
- **Tracking GPS de los autobuses (Icono moviéndose):** Mantener el código actual (`getBusLocation` en `crtmService.js`) ya que el CRTM sí proporciona coordenadas bastante útiles, y hemos optimizado el `setTimeout` recursivo a 20s para que no sature la red.

---
**Recordatorio de arquitectura actual (Graceful Degradation):**
Si no se aplica la mejora híbrida, el código actual ya está defendido con un patrón de reintentos asíncronos (Backoff Exponencial) que captura los fallos de red y evita que la app crashee, lo cual es una defensa muy buena para explicar en la presentación del TFC.
